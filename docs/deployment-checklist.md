# Deployment Checklist

This checklist defines what should be reviewed before a CI/CD pipeline deploys
a Java or Spring Boot application.

## Before Deployment

- The target branch is correct.
- The latest commit was reviewed or approved.
- The test stage passed.
- The package or image build stage passed.
- The generated artifact is traceable to the pipeline run.
- Required environment variables are configured.
- Required credentials exist in Jenkins or a secret manager.
- The deployment target is clear.
- Rollback expectations are known.

## Artifact Checks

Confirm that the deployable artifact is:

- generated by the pipeline;
- stored or published in a known location;
- tagged with a build number, commit SHA, or release version;
- not produced manually outside CI;
- reproducible from source control.

## Environment Checks

Confirm that the target environment has:

- the expected Java version;
- the expected database configuration;
- the expected external service configuration;
- health check endpoints available;
- logs and metrics configured;
- enough permissions for the deployment action.

## Approval Criteria

Automatic deployment can make sense when:

- the environment is development or staging;
- tests are reliable;
- rollback is simple;
- the team wants fast feedback.

Manual approval is safer when:

- the environment is production;
- database migrations are included;
- customer-facing behavior changes;
- infrastructure or credentials change;
- rollback requires coordination.

## After Deployment

- Check application health endpoints.
- Verify logs for startup errors.
- Confirm metrics are being emitted.
- Validate one critical user flow.
- Confirm the deployed version matches the expected artifact.
- Record any incident or unexpected behavior.

## Interview Talking Points

- Deployment is an engineering decision, not only a button click.
- Good pipelines separate build confidence from release approval.
- Production deployment should include rollback and observability thinking.
- Traceability matters because teams need to know what is running.
